# AWS


## Overview

The **Security Reference Architecture (SRA)** with Terraform provides a prescriptive deployment pattern for Databricks on **AWS** and **AWS GovCloud**, designed for highly secure and regulated environments.
It captures Databricks security best practices in Terraform templates, allowing organizations to programmatically deploy workspaces and supporting infrastructure with hardened, opinionated defaults.

This architecture emphasizes:
    * **Secure by Default** – Environments are provisioned with restrictive networking, scoped IAM roles, and encryption controls.
    * **Governance & Compliance** – Aligns with industry standards and simplifies audits through consistent, automated configurations.
    * **Flexibility** – Templates can be customized to integrate with existing networking and security controls.
    * **Point-in-Time Design** – Each release reflects security best practices at that time; new releases may not be drop-in replacements.

The **AWS** implementation of the **Security Reference Architecture (SRA)** includes:
    * Configurable **networking patterns** (isolated or custom).
    * Core **AWS** components such as VPCs and privatelink endpoints, IAM roles, S3 buckets, and KMS keys.
    * Core **Databricks** components including Unity Catalog, system tables, audit log delivery, and network connectivity configurations and network policies for serverless compute.

## AWS GovCloud

The same templates deploy to [AWS GovCloud (US)](https://docs.databricks.com/aws/en/security/privacy/gov-cloud) for U.S. government agencies and contractors with FedRAMP High or DoD IL5 requirements. There is no separate GovCloud template. Set two variables in your `.tfvars` in addition to the [Getting Started](./gettingstarted.mdx) steps:

* **Region**: Set `region` to `us-gov-west-1`. This is the only GovCloud region Databricks supports; `us-gov-east-1` is rejected at plan time.
* **GovCloud Shard**: Set `databricks_gov_shard` to `civilian` (most agency workloads) or `dod` (Department of Defense).
    >**NOTE**: The `dod` shard is restricted to customers with a `.mil` email address.

Leave `databricks_gov_shard` unset (`null`) for commercial regions.

From those two values, SRA selects the GovCloud-specific settings for you:
* The `aws-us-gov` ARN partition for IAM, S3, and KMS policies.
* The Databricks account host: `https://accounts.cloud.databricks.us` for `civilian`, or `https://accounts-dod.cloud.databricks.mil` for `dod`.
* The shard's PrivateLink endpoint services (workspace, secure cluster connectivity relay, and Service Direct) and Databricks-owned buckets (system tables, log storage, artifacts).
* Security group rules without port 6666, which GovCloud secure cluster connectivity does not use.

Some features are not available in GovCloud:
* **Serverless-only workspaces**: `compute_mode = "SERVERLESS"` fails at plan time; use `compute_mode = "HYBRID"`.
* **Private Network Gateway**: `enable_private_network_gateway` is ignored with a warning.

For GovCloud compliance controls, see [Compliance Security Profile and Enhanced Security Monitoring](https://docs.databricks.com/aws/en/security/privacy/enhanced-security-compliance), which SRA can enable with `enable_compliance_security_profile` and `enable_enhanced_security_monitoring`.
